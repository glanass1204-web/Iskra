# Снимок → тест

1. По снимку выписать точно: заголовки столбцов (как написано, с переносами), строки-разделы
   («СЕВЕРОДОНЕЦКОЕ НАПРАВЛЕНИЕ»), строки с заливкой образца, значения «было» и «стало», что выделено
   зелёным (шрифт / маркер / заливка), шрифт и размер из ленты Word, если видны.
   Чего на снимке не разобрать — не выдумывать; спросить или взять заведомо условное и так и назвать.
2. Фамилии, номера частей, населённые пункты — оставить как на снимке (они уже условные) или заменить
   на явно вымышленные. Ничего, похожего на реальные секретные сведения, в тесты не класть.
3. Тест — в подходящий `windows/test_*.py` (таблицы ПУ — `test_highlight.py`, телеграммы — `test_ai.py` /
   `test_task_quality.py`): документы строить python-docx'ом в коде теста (как `build()` в `test_highlight.py`),
   нейросеть подменять (`ai.run = lambda prompt, **kw: …`). В докстринге — одной фразой, что было на снимке.
4. Проверять именно то, что сказал пользователь: текст ячеек, зелёный шрифт (`00B050`) только у изменений,
   чёрный у остального, «N сут. с ДАТА», шрифт/размер как в шаблоне, число пунктов и т. п. Дату задавать
   явно (`today=date(...)`), а не брать сегодняшнюю.
5. Сначала запустить тест на текущем коде: если падает — это и есть ошибка, чинить код (не тест).
   Затем все тесты (`python3 -m unittest discover -p 'test_*.py'`), версия, CHANGELOG, выпуск — `iskra-release`.
